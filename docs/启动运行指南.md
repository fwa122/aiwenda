# 启动运行指南（含 Docker 使用说明）

> 本文档回答一个问题：**这套系统怎么跑起来**。三种方式按场景选一种即可；
> 「开发模式」与「Docker 部署」的数据互相独立，不要混用。

---

## 一、系统组成：跑起来后是什么样

Docker 部署成功后，本机会运行 **6 个容器**（项目名 `kb-prod`）：

| 容器名 | 镜像 | 职责 | 对外端口 |
| --- | --- | --- | --- |
| `kb-prod-nginx-1` | aiwenda-frontend | 前端静态资源 + `/api` 反向代理 | **80**（唯一入口） |
| `kb-prod-server-1` | aiwenda-server | Node BFF：鉴权、业务、SSE 编排 | 内部 3000 |
| `kb-prod-ai-service-1` | aiwenda-ai | Python AI 服务：检索、生成、流式输出 | 内部 8000 |
| `kb-prod-worker-1` | aiwenda-ai（同镜像） | Celery worker：异步解析文档 | 无 |
| `kb-prod-postgres-1` | pgvector/pgvector:pg16 | 业务数据 + 向量存储 | 内部 5432 |
| `kb-prod-redis-1` | redis:7-alpine | 任务队列 | 内部 6379 |

要点：
- **只有 nginx 暴露端口**，其余服务都在容器内网通信，数据库密码不 出网
- 首次启动 server 容器会**自动执行数据库迁移 + 创建 admin 账号**，无需手动初始化
- 数据保存在三个命名卷：`kb-prod_pg_data` / `kb-prod_redis_data` / `kb-prod_uploads_data`，删容器不丢数据

## 三、方式一：现成镜像一键部署（推荐）

> 免构建、免 Node/Python 环境，首次部署约 5 分钟（大部分时间在拉镜像）。

### 第 1 步：获取代码并写配置

```bash
git clone https://github.com/fwa122/aiwenda.git
cd aiwenda

# Windows PowerShell 用 copy；Git Bash / Linux / Mac 用 cp
copy .env.docker.example .env      # Windows
# cp .env.docker.example .env      # Linux / Mac
```

编辑 `.env`，**必填 4 项**：

| 变量 | 用途 | 生成方式（Git Bash 执行） |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | 数据库密码（仅容器内网用） | `openssl rand -hex 16` |
| `JWT_SECRET` | 登录令牌签名密钥 | `openssl rand -hex 32` |
| `INTERNAL_TOKEN` | BFF↔AI 服务内部令牌 | `openssl rand -hex 32` |
| `ZHIPU_API_KEY` | 智谱开放平台控制台复制 | —（直接粘贴） |

> Windows 没有 openssl？用 Git Bash 执行，或在 PowerShell 里生成：
> `-join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })`
>
> 常用可选项：`MOONSHOT_API_KEY`（接入 Kimi）、`NGINX_PORT`（默认 80，被占用时改成如 `8080`）、`FRONTEND_URL`（部署到服务器后设为 `http://<服务器IP>`，影响 CORS 白名单）。

### 第 2 步：拉镜像并启动

```bash
docker compose -f docker-compose.prod.yml pull     # 拉取 6 个镜像
docker compose -f docker-compose.prod.yml up -d    # 后台启动全部容器
```

### 第 3 步：验证

```bash
docker compose -f docker-compose.prod.yml ps       # 6 个容器应为 Up / Up (healthy)
```

浏览器打开 `http://localhost/`（云服务器用 `http://<服务器IP>/`），用 `admin / admin123` 登录，**立即改密码**，然后：新建知识库 → 上传一份 PDF → 等解析完成 → 提问，能看到流式回答和引用编号即为部署成功。

### 国内拉镜像慢/超时

```bash
# 基础镜像可走 DaoCloud 加速后重打标签
docker pull docker.m.daocloud.io/library/python:3.12-slim
docker tag docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim
# nginx:alpine、node:24-slim 同理；个人镜像需在 Docker Desktop → Settings → Resources → Proxies 配置代理
```

## 四、方式二：源码构建部署（改了代码时用）

```bash
docker compose up -d --build    # 首次约 5~10 分钟，之后增量构建
```

服务定义与方式一完全相同，区别仅是前端/BFF/AI 三个镜像从本地源码构建。改代码后重复执行即可更新。

## 五、方式三：本地开发模式（调试用）

### 一键启停（Windows）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1   # 启动
powershell -ExecutionPolicy Bypass -File scripts\stop-all.ps1    # 停止
```

脚本按端口精确启停、幂等（已在运行的服务自动跳过）：Docker 基础设施 → Python AI 服务（uvicorn + Celery worker）→ Node BFF → 前端 Vite。

### 分模块手动启动

```bash
# 0. 基础设施（PostgreSQL16+pgvector / Redis7）
docker compose -f docker-compose.infra.yml up -d

# 1. 前端
cd frontend && npm install && npm run dev          # http://localhost:5173

# 2. Node BFF（首次先迁移+播种）
cd server && npm install
npx prisma migrate deploy && npx prisma db seed
npm run build && npm start                         # http://localhost:3000/api/v1

# 3. Python AI 服务（首次先建 venv 装 requirements）
cd ai-service
uvicorn app.main:app --host 127.0.0.1 --port 8000
celery -A app.tasks:celery_app worker --pool=solo --loglevel=info
```

各模块的 `.env` 参考各自的 `.env.example`。**开发模式的数据与 Docker 部署互不相通。**

## 六、日常运维命令速查

> 以下均在项目根目录执行；`-f docker-compose.prod.yml` 每条都要带（可自行设置别名）。

| 操作 | 命令 |
| --- | --- |
| 看容器状态 | `docker compose -f docker-compose.prod.yml ps` |
| 停止（数据保留，秒起） | `docker compose -f docker-compose.prod.yml stop` |
| 再次启动 | `docker compose -f docker-compose.prod.yml up -d` |
| 看某服务日志（实时） | `docker compose -f docker-compose.prod.yml logs -f server` |
| 更新到新版本 | `git pull && docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d` |
| 只重启单个服务 | `docker compose -f docker-compose.prod.yml restart server` |
| 删容器（数据仍在卷中） | `docker compose -f docker-compose.prod.yml down` |
| ⚠️ 连数据一起清空 | `docker compose -f docker-compose.prod.yml down -v`（仅重置环境用） |

### 数据备份与恢复（PostgreSQL）

```bash
# 备份（导出 SQL 到当前目录）
docker exec kb-prod-postgres-1 pg_dump -U kb kb > backup.sql

# 恢复
docker exec -i kb-prod-postgres-1 psql -U kb -d kb < backup.sql
```

上传的原文文件在命名卷 `kb-prod_uploads_data` 中，一并备份需复制卷数据。

## 八、常见问题排查（FAQ）

| 现象 | 原因与解决 |
| --- | --- |
| 80 端口被占用（Windows 上常见于 Docker Desktop 代理占用） | `.env` 里设置 `NGINX_PORT=8080`，重新 `up -d`，改用 `http://localhost:8080/` 访问 |
| 拉镜像超时 / `registry-1.docker.io` 连不上 | 见「三 · 国内拉镜像慢」：配置代理或镜像加速 |
| 容器起了一直 restarting | `docker compose -f docker-compose.prod.yml logs server` 看报错；最常见是 `.env` 少填/错填（JWT_SECRET 强度不足会启动即失败） |
| 页面能开、提问无响应 | 依次查 `logs ai-service` 与 `logs server`；确认 `ZHIPU_API_KEY` 有效、`INTERNAL_TOKEN` 两边一致 |
| 文档一直"解析中" | 查 `logs worker`；Celery worker 没起来或 Redis 未就绪 |
| 登录报 401 | JWT_SECRET 改过会导致旧令牌失效，退出重新登录即可 |
| 云服务器访问不了 | 云厂商**安全组**放行 80（或自定义 NGINX_PORT）端口；`.env` 设 `FRONTEND_URL=http://<服务器IP>` |
| 忘记 admin 密码 | `docker compose -f docker-compose.prod.yml down -v` 重置（清空数据重建），或进 PG 手动重置哈希 |

## 九、部署到云服务器的检查清单

1. 安全组/防火墙放行 `NGINX_PORT`（默认 80）
2. `.env` 四个必填项全部使用**新生成的随机值**（不要沿用示例值）
3. `FRONTEND_URL` 设为实际访问地址
4. 登录后**立即修改 admin 密码**，并关闭注册开关（系统设置）
5. 建议后续：绑定域名 + HTTPS（certbot）、配置数据库定期备份 cron
