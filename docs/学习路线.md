# AI 知识库问答系统 — 系统性学习路线（简历/面试向）

> 目标岗位：**AI 应用开发**。学习方式：**代码精讲 → 费曼复述 → 面试追问 → 自测过线** 四步循环。
> 原则：不是把项目"背下来"，而是把每个设计决策的 **为什么** 讲清楚——面试官区分背稿和真懂的方式就是连续追问三层。
> 现状基线：v0.9.41，全栈已交付，自动化测试 146+ 用例，CI/CD 全绿。已有《答辩讲述稿》是答辩口径，本路线按面试深挖口径重建。

---

## 总览：六个阶段

| 阶段 | 主题 | 面试权重 | 状态 |
| --- | --- | --- | --- |
| 0 | 全局地图与讲述框架 | ★★★（决定第一印象） | ⬜ 未开始 |
| 1 | RAG 主链路（解析→切片→向量→检索→生成） | ★★★★★（AI 岗灵魂） | ⬜ 未开始 |
| 2 | AI 工程化（评测/缓存/多模型/异步任务） | ★★★★★（差异化亮点） | ⬜ 未开始 |
| 3 | 后端工程支撑（鉴权/权限/数据模型/BFF 编排） | ★★★（讲清楚即可） | ⬜ 未开始 |
| 4 | 部署与可靠性（Docker/nginx/CI/CD） | ★★（快速过） | ⬜ 未开始 |
| 5 | 面试实战（简历打磨/模拟面试/八股关联） | ★★★★（临门一脚） | ⬜ 未开始 |

每个阶段的推进节奏（单次学习会话 1~2 小时为宜）：
1. **精讲**：我带你读核心代码，讲清"做了什么、为什么这么做、不这么做会怎样"；
2. **复述**：你合上文档，用自己的话讲一遍（费曼），卡壳处就是盲区；
3. **追问**：我以面试官视角就本阶段提问，从表面追到实现层再到权衡层；
4. **过线**：达成该阶段的「过线标准」才进入下一阶段。

## 阶段 1：RAG 主链路（核心中的核心）

### 1a 文档处理流水线
**精读**：`ai-service/app/parser.py`（PDF 标题启发式还原结构、表格转 Markdown、扫描件 OCR 兜底）、`ai-service/app/tasks.py`（Celery 解析任务、软/硬超时 30/35min、卡死对账自愈）

**必须能回答**
- 为什么切片前要先"还原文档结构"？直接按固定字数切会丢什么？
- 标题启发式的具体规则是什么？失败时怎么降级？
- 解析任务卡在 pending/in-progress 怎么自愈？（每 5 分钟对账、超时阈值重置重派）
- 为什么超时任务标记失败而不做指数退避重试？

### 1b 切片策略
**精读**：`ai-service/app/chunker.py`（按标题层级切、heading 注入切片首行、相邻小段合并）

**必须能回答**
- 切片太大/太小各自的问题？你的策略怎么同时缓解两者？
- 为什么把标题注入切片首行？（让向量携带章节上下文——这是"上下文增强切片"思想）
- 有没有量化的切片质量评估？（诚实回答：靠检索评测间接验证，这是可以讲的"已知不足"）

### 1c 向量化与嵌入管理
**精读**：`ai-service/app/embedding.py`（批量嵌入、分 provider 批量上限：千问 20/批 vs 智谱 32/批）、`embedding_cache` 表（sha256(provider:model:dim:content) 主键、30 天 TTL、advisory lock 建 DDL）

**必须能回答**
- 为什么换嵌入模型必须全库重嵌入？（不同向量空间不可比——能讲出这句话背后的数学含义是加分项）
- 嵌入缓存的主键为什么这样设计？崩溃重跑为什么不会重复计费？
- 千问 vs 智谱嵌入在你项目里的实测对比？（MRR@5 0.693 → 0.8267，这是一手实验数据，很值钱）

### 1d 检索内核（面试最深处，多留时间）
**精读**：`ai-service/app/retrieval.py` —— 双路召回（向量 + pg_trgm 词法）→ RRF 融合（k=60）→ rerank 精排 → 降级链

**必须能回答**
- 纯向量检索的短板？（专有名词/编号等字面匹配不敏感——所以才有混合检索）
- **RRF 公式默写**：Σ 1/(k+rank)，为什么只看排名不看原始分？（两路分数量纲不可比）k=60 的作用？
- rerank 和向量检索的区别？（bi-encoder vs cross-encoder，为什么 cross-encoder 更准但更贵）
- 完整降级链：rerank 挂了→回退 RRF 排序；词法扩展不可用→候选池内兜底；为什么保证"检索永远有结果"？
- 自适应 rerank 跳过（Top1−Top2 分差 ≥0.03 跳过精排）：为什么做了又把结论推翻？（阈值在旧嵌入空间标定，换空间后分布重排——这个"自我否定"的实验故事面试官很爱听）
- 多轮对话查询改写：指代消解（"那它多少钱"→完整查询）、启发式跳过条件、历史钳制 4000 字符

**动手验证**：启动本地环境，检索测试页做消融实验（Top-K/阈值/混合/rerank 开关对比），亲手跑一遍 MRR 计算。

### 1e 生成与防幻觉
**精读**：`ai-service/app/api/internal.py`（上下文字符预算截断、[n] 编号引用、系统提示词约束、生成后校验补来源）

**必须能回答**
- 三道防幻觉防线分别是什么？各自拦什么？
- 检索为空时为什么直接不调 LLM？（省成本 + 防编造）
- 引用编号怎么保证不指向错来源？（附件不占编号、生成后校验无 [n] 自动补来源）
- SSE 事件序列（references → delta… → done）各事件载荷什么？

**过线标准**：RRF 公式白板默写并解释每个参数；降级链画出分支图；能完整讲述一次提问在 retrieval.py 里的执行路径。

## 阶段 2：AI 工程化能力（差异化亮点，AI 岗重点加分）

### 2a 检索评测体系（绝大多数候选人没有，重点准备）
**精读**：`ai-service/tests` 相关评测脚本、`knowledge-base` 模块评测 tab 逻辑、`docs/更新日志.md` v0.9.10/v0.9.11 段

**必须能回答**
- golden 20 QA 怎么构建的？hit 判定规则（目标文档 + |chunk_index−anchor|≤1 + 关键词兜底）为什么这样定？
- **MRR@5 怎么算？为什么用 MRR 而不是 Accuracy？** bootstrap 95% CI（1000 次重采样）为什么必要？（"单点估计会说谎，置信区间不会"——rerank on 0.6867 vs off 0.693 的实测教训）
- 难例回流闭环：评测未命中 → 一键标记难例 → 转正式评测用例 → 回归验证，能画出这个环
- aggregate 指标对不上时怎么排查？（per-case ground truth 逐案对比——这是方法论级别的回答）

### 2b 语义缓存
**精读**：`ai-service/app/answer_cache.py`

**必须能回答**
- 什么条件下可缓存？（useCache && kbIds 非空 && 单轮 && 无附件——为什么多轮/附件会"串答"）
- 命中机制：kb_hash（去重排序 md5）+ question_norm 唯一 + embedding HNSW 近邻，为什么问题也要向量化？
- 缓存失效联动：文档上传/重解析/删除、库删除/重建、全库重嵌入都要 fire-and-forget 失效——为什么？
- 统计口径：命中重放的 tokens 为什么 billable=0？（防 daily_stats 虚报）
- 写缓存为什么放在 yield done 之后？（客户端中断 → GeneratorExit → 天然只缓存完整答案）

### 2c 多模型接入层
**精读**：`ai-service/app/llm.py`（模型注册表、前缀路由 glm-*→智谱 / kimi-*→Moonshot）、`ai-service/app/keystore.py`（DB 密钥读取 45s TTL 缓存）

**必须能回答**
- 注册表模式的好处：新增 Provider 只注册不改调用方——对比 if/else 写法说清楚
- 轻量任务（改写/建议/命名）为什么必须走注册表回落而不能硬编码模型名？（v0.9.13 的静默故障教训：建议功能空数组跑了很久没发现）
- 各家 API 的坑：Kimi temperature 强制 0.6 + thinking 显式 disabled；千问思考模式默认开要注入 enable_thinking=False；MiniMax reasoning_split 拆思考、max_tokens 含思考 token——**每家都能讲出一个具体坑，是"真的接过"的证明**
- SSE 流式在各家的实现差异

### 2d 异步任务体系
**精读**：`ai-service/app/tasks.py`、Celery 配置

**必须能回答**
- 为什么解析要走 Celery 异步？（耗时重活不阻塞 web 进程）
- worker 连接池的坑：fork 后共享 socket 损坏、长时间空闲 PoolTimeout——踩过的坑能讲出根因和修法
- 嵌入缓存表为什么用 advisory lock 建？（prefork 多进程并发 DDL 冲突）

**过线标准**：能画出评测闭环图并报出关键数字（MRR@5 0.8267、20 条 golden、1000 次重采样）；能讲出 3 个以上"踩坑→根因→修法"的完整故事。

## 阶段 5：面试实战

- **简历项目描述打磨**：3~5 行 STAR 口径，埋好"钩子"（面试官顺着钩子问，正好问到你准备最深的点）

- **数字卡终版**：容器数/表数/测试用例数/MRR 提升/CI 时长等，全部能报出出处

## 附：跨阶段通用原则

1. **每个结论都带出处**："MRR 0.8267 是千问嵌入在 golden 20 上实测的"远好于"效果还不错"。
2. **准备 3 个失败故事**：面试官要的是判断力，判断力来自踩坑。候选：rerank 阈值失效、轻量任务静默故障、MinIO 官方镜像下架事件。
3. **诚实边界**：被问到没做的（如切片质量量化评估、多租户隔离），答"已知不足 + 我会怎么补"，比硬编强得多。
4. **进度记录**：每完成一个阶段，把「状态」列改为 ✅ 并注明日期；卡壳的追问记录在对应阶段末尾，作为下次复习重点。
