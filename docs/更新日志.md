## v0.9.3 — 2026-10-05

### 新增

- **聊天页拖拽直接入库**（`frontend/src/views/ChatView.vue`）：文件拖入聊天页任意位置 → 全屏遮罩提示目标知识库（未选库时引导先选择）→ 按白名单（pdf/docx/txt/md/csv）与 20MB 上限过滤并逐条说明拒绝原因 → 入当前知识库并启动解析监听。拖拽入库与附件临时问答是两条独立路径，互不影响。技术要点：dragleave 抖动用进出计数器抵消；浏览器通知权限在 drop 用户手势内请求（符合 Notification API 的授权约束）。
- **文件夹批量导入**（知识库列表页「文件夹导入」按钮，`webkitdirectory`）：按 `webkitRelativePath` 首段目录名分组，同名知识库自动复用、缺库自动创建；隐藏文件 / 超限 / 非白名单文件跳过并汇总原因；每组 >10 个文件自动分批（对齐后端单次上限）；单组失败不阻塞后续组；完成后统一汇总通知并启动各库解析监听。
- **解析完成浏览器通知**（新增 `frontend/src/composables/useParseWatcher.js`）：5 秒轮询文档状态（单库最长监听 5 分钟自动停止），文档到达 `parsed` / `failed` 时发应用内通知（成功 5s / 失败 8s 存活）+ 浏览器系统通知（权限 denied 时静默降级）；同库重复监听自动合并目标、不叠加定时器；全部终态后自停。聊天页拖拽导入、文件夹导入、知识库详情页上传三条入口均已接入。

### 修复

- **知识库状态可能永久卡在「索引整理中」**（`ai-service/app/tasks.py`）
  - 现象：库内所有文档均已 `parsed`，但知识库状态停留在 `indexing`，导致聊天页知识库下拉（只列 ready 库）显示「无数据」
  - 原因：状态回写是"最后一次解析任务完成时打上 ready"，任何晚于它的状态写入（如删除/重建期间的并发更新）都会把库打回 `indexing`，且此后无任务再触发回写——乱序后永不自愈
  - 方案：任务完成时改为**按剩余工作量判定**——库内仍存在 `pending/parsing/indexing` 文档则保持现状，否则无条件归位 `ready`；每次任务完成都是一次自愈机会
  - 验证：重启 worker 后实测，任务消费成功且 KB 状态自动归位 `ready`，下拉接口恢复返回
- **通知可读性**：解析完成/失败通知存活时长 3s → 5s/8s（原 3 秒过短易被错过）
- **运维**：清理重复的 Celery worker（系统 Python 与 .venv 各一个，会竞争消费队列），统一以 `.venv` 单实例运行

### 测试

- 浏览器端到端（合成 DragEvent）：拖拽遮罩 → 入库 → 「导入成功」→「解析完成」通知全链路 PASS；文件夹导入按钮与 `webkitdirectory` 输入渲染 PASS；控制台无报错
- 任务链路：手动补投解析任务，worker 消费成功（切片 + 向量化 + 状态自愈）；测试产生的 6 个文档已通过 API 清理，知识库恢复 4 份真实文档

### 后续计划

- **粘贴截图提问**：聊天输入框粘贴图片 → glm-ocr 识别 → 文本作为临时附件上下文提问。需后端配套扩展（上传白名单与 ai-service 解析器当前均不支持图片格式），作为独立后端任务另行实施。

## v0.9.2 — 2026-10-05

### 新增

- **文档在线预览与下载**（知识库详情页 · 文档列表）
  - 接口：`GET /v1/documents/:id/file?mode=inline|attachment`，单端点双模式——`inline` 预览 / `attachment` 下载，`StreamableFile` 流式返回（大文件不占内存）
  - 前端：文档列表操作列新增「预览 / 下载」；预览抽屉按格式分流——PDF 走 iframe 原生渲染、Markdown 复用 `renderMarkdown` 渲染、TXT/CSV 纯文本展示、DOCX 引导下载
  - 技术要点：文件传输走原生 `fetch → Blob → URL.createObjectURL()`（iframe 无法携带 `Authorization` header，且原生 fetch 天然绕过 axios 拦截器的 JSON 解包）；文件 URL 永不裸露
  - 安全设计：路径完全由服务端生成的 `storageKey` 推导（拒绝用户可控路径）+ `resolve` 前缀二次校验防穿越；MIME 按扩展名白名单映射，未知类型拒绝；文件名 RFC 5987 编码（中文不乱码、防 header 注入）
  - 权限与审计：复用知识库可见性权限模型（`kb-access`）；**下载一律写 `operation_logs` 审计，private 库的在线预览同样记录**

### 交互优化

- **文件名悬停显示全名**（知识库详情页 · 文档列表）：超长文件名截断省略后，鼠标悬停 300ms 弹出 tooltip 显示完整名称（顶部对齐），快速扫过表格时气泡不干扰；浏览器实测确认气泡真实渲染（`display:block / opacity:1`）。

### 修复

- **全局响应拦截器误包装文件流**（`server/src/common/response.interceptor.ts`）
  - 现象：文件接口 HTTP 200、Content-Type 正确，但响应体是 `{code:0, data:{stream:...}}` 的 JSON 包装，前端拿到的是序列化对象而非原始内容
  - 原因：统一响应包装拦截器对所有 controller 返回值生效，`StreamableFile` 也被 `serializeBigInt` 转成普通对象再 JSON 序列化
  - 方案：拦截器对 `StreamableFile` 直通——流式/二进制响应必须绕过为 JSON 设计的包装层（与 SSE 绕过拦截器同理）
- **知识库详情「字段接缝」缺陷：文档列表空白但统计正常**（`frontend/src/api/knowledge.js`、`KnowledgeDetailView.vue`）
  - 现象：详情页统计行显示文档数 3，文档列表却始终「暂无文档」；配置 tab 保存检索参数后不生效
  - 原因：Mock 数据与真实后端字段名不一致（前端 `retriever`/`llm` vs 后端 `retrieverConfig`/`llmConfig`）。挂载时读取 `kb.retriever.topK` 抛 `TypeError`，中断在列表加载之前；写方向嵌套 `retriever` 对象被后端（扁平字段契约）静默丢弃
  - 方案：在 API 边界统一归一化（`normalizeKb` 读方向映射、写方向拍平为后端契约的扁平字段），视图层永远面对单一数据形状；视图侧补 `?.` 可选链防回归
  - 教训：Mock 与真实后端的数据形状差异必须收敛在 API 接缝层，而不是散落在视图代码里
- **知识库状态卡在「索引构建中」**：3 份文档早已 `parsed`，KB 状态未回写（历史解析残留），一次性数据修复置为 `ready`
- **中文文件名上传乱码**（`server/src/document/document.service.ts`）
  - 现象：上传中文命名的文件后，列表中文件名显示为 `Ã¨Â°…` 形式乱码（如「许昌学院2026年…」变成 `è®¸æå­¦é¢2026å¹´…`）
  - 原因：multipart 中的 `filename` 是 UTF-8 字节，Multer 按 latin-1 解码成字符串，中文字节被逐字节错读
  - 方案：新增 `fixFilenameEncoding()`——按 latin-1 还原原始字节再按 UTF-8 解码；带**双向保护**：纯 ASCII 名与无 latin1 扩展区字符的名字原样保留，还原结果含 U+FFFD 替换符的（说明并非 latin1 乱码）同样保留，避免误伤
  - 验证：中文文件名上传回归 PASS（`测试文档.md` 正确入库）；存量乱码数据已用同算法还原修复
  - 附带发现：Celery worker 与解析链路实测正常（PDF 重解析 8 秒完成、10 切片），此前「排队中」为任务等待 worker 的瞬时状态

### 测试

- 接口回归 9 项全过：md/PDF/中文文件名的 inline + attachment、无 token 401、不存在 id 404、下载审计落库；拦截器改动后 JSON 接口（文档清单/切片/详情）信封结构回归正常
- 浏览器端到端：列表 5 操作按钮、Markdown 预览渲染、下载触发、控制台无新增报错

### 修复

- **聊天输入框「检索设置」按钮点击无反应**（`frontend/src/components/ChatInput.vue`）
  - 现象：点击按钮后设置弹层（TopK / 相似度阈值 / 混合检索开关）不出现，无任何反馈
  - 原因：`el-popover` 的 `#reference` 槽内嵌套了 `el-tooltip`（组件）。Element Plus 要求该槽为真实 DOM 元素，嵌套组件导致弹层触发器绑到"非元素根节点"，弹层节点虽挂载但恒为 `display: none`；控制台伴随警告 `Runtime directive used on component with non-element root node`
  - 方案：改用官方 virtual-ref 模式——popover 通过 `:virtual-ref` 绑定按钮引用，tooltip 独立包裹同一按钮，两者解耦嵌套
  - 验证：浏览器实测弹层正常弹出（display:block）、tooltip 正常、控制台警告消失

### 文档

- **2026-09-30** 新增《[答辩讲述稿](./答辩讲述稿.md)》：3 分钟项目讲述稿 + 关键数字卡 + 10 个高频追问应答要点 + 排练提示。
